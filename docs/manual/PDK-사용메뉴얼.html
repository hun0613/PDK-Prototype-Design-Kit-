1PDK란

기획자가 Claude에게 말로 설명하면 화면설계서를 만들어 주는 템플릿입니다. 설치할 프로그램도, 코드를 쓸 일도 없습니다.

무엇이 만들어지나

결과물내용
페이지 목록등록한 화면 전체 목록 (화면 ID · 이름 · 진행 상태)
화면 플로우화면이 어디서 들어와 어디로 가는지 그린 다이어그램
기능명세서엑셀로 쓰던 그 표 (기능 ID · 위치 · 대상 · 상세 · 우선순위)
와이어프레임실제 문구가 들어간 흑백 화면 — 버튼을 누르면 다음 화면으로 이동
Description화면 옆 설명 패널 (마우스를 올리면 해당 요소가 강조됨)

알아 둘 것

  • 브라우저로 열면 바로 보입니다 — 설치·빌드 과정이 없습니다.
  • 목업 기기 4종 내장 — 데스크탑 / 모바일 / 토스프론트2 / 반응형. 다른 기기도 추가할 수 있습니다.
  • 색·폰트 같은 디자인은 Figma에서 관리합니다. PDK는 구조와 흐름까지입니다.
화면은 3단계로 자랍니다.
① /pdk-screen 등록 (이름·ID만) → ② /pdk-wireframe 흑백 UI → ③ /pdk-figma-sync 디자인 반영

2준비

딱 세 가지만 하면 됩니다.

① 폴더 내려받기

PDK 레포를 클론하거나 ZIP으로 받아 압축을 풉니다. 받은 폴더를 내 작업 폴더로 씁니다.

② 그 폴더에서 Claude Code 열기

터미널에서 폴더로 이동한 뒤 claude 를 입력하거나, VS Code 확장에서 그 폴더를 엽니다. 이제부터는 Claude에게 커맨드만 입력합니다.

③ (선택) 미리보기 서버 띄우기

python -m http.server 8124   # → 브라우저에서 http://localhost:8124

서버 없이 index.html 파일을 더블클릭해 열어도 됩니다.

처음엔 비어 있는 게 정상입니다. 받은 직후에는 등록된 화면이 없어 목록·플로우가 모두 빈 상태입니다. 다음 단계부터 채워집니다.

4STEP 1 — 프로젝트 시작

/pdk-init

Claude가 차례로 물어봅니다. 순서대로 답하면 됩니다.

질문답하는 법
프로젝트 이름그대로 적습니다 (예: 더베스트페이 가맹점센터)
프로젝트 코드영문 약어. 기능 ID 앞에 붙습니다 (예: GFC → GFC-FUC-001)
프로젝트 설명한두 줄
디바이스데스크탑 / 모바일 / 토스프론트2 / 반응형 중 하나
PRD 문서 (선택)docs/prd/ 에 넣어 둔 HTML 파일명. 상단 바에 PRD 문서 보기 버튼이 생깁니다
내 레포 주소작업 결과를 올릴 곳. 없으면 "나중에" 라고 답하면 됩니다
왜 레포 주소를 묻나요? 받은 폴더는 PDK 원본을 가리키고 있어, 그대로 올리면 템플릿 레포에 내 작업이 밀려 들어갑니다. /pdk-init 이 이 연결을 끊거나 내 레포로 바꿔 줍니다. "나중에"라고 답해도 안전합니다.
  • 반응형을 고르면 상단 바 우측에 데스크탑/모바일 토글이 생깁니다.
  • 다시 실행해도 이미 등록한 화면·설정은 그대로 남습니다. PRD는 나중에 붙여도 됩니다.

(선택) 다른 기기를 쓰고 싶다면 — STEP 1 이전에

/pdk-mockup my-kiosk ./목업이미지폴더
/pdk-mockup my-kiosk https://www.figma.com/design/...?node-id=12-34
  • 이미지가 여러 장이면 Claude가 어느 걸 쓸지 물어봅니다.
  • 화면 가로×세로(px) 를 직접 입력합니다.
  • 등록하면 /pdk-init 의 디바이스 목록에 나타납니다.

5STEP 2 — 화면 등록

화면을 사용자가 지나가는 순서대로 하나씩 등록합니다. 가장 많이 쓰는 단계입니다.

/pdk-screen 공통 SCR-MAIN-001 메인
/pdk-screen 주문 SCR-LIST-001 상품목록

# 형식: /pdk-screen [카테고리] [화면ID] [화면이름]

Claude가 묻는 세 가지

  1. 언제·어떻게 보이는 화면인가요? — 화면의 맥락
  2. 어디서 들어오나요? — 예: 메인에서 "시작하기" 버튼
  3. 다음에 어디로 가나요? — 갈래가 나뉘어도 됩니다 (예: 결제 성공→완료 / 실패→실패)

결과

  • 화면 HTML이 pages/ 폴더에 생깁니다 (index.html 만 폴더 바깥에 있습니다).
  • 페이지 목록 · 화면 플로우 · Description이 자동으로 그려집니다.
없는 화면을 말해도 괜찮습니다. "결제 실패하면 실패 화면으로" 라고 하면 그 화면도 그 자리에서 만들어집니다. 이름·카테고리만 묻고, 그 화면의 다음 이동은 나중에 그 화면 차례에 물어봅니다.

나중에 채우거나 고치기

화면 ID만 주면 됩니다. 비어 있는 항목만 물어보고 이미 쓴 내용과 만들어 둔 화면은 건드리지 않습니다.

/pdk-screen SCR-PAY-002
화면 ID 권장 형식 — SCR-<카테고리약어>-<세 자리> (예: SCR-PAY-001)

6STEP 3 — 기능명세서

화면을 그리기 전에, 그 화면에 어떤 기능이 있어야 하는지 글로 먼저 정리합니다. 엑셀로 쓰던 기능명세서와 같은 형식입니다.

/pdk-description SCR-SALE-001
  • Claude가 화면 맥락·이동·PRD를 보고 기능 목록 초안을 먼저 보여줍니다. 추가·삭제·수정만 말하면 됩니다.
  • 처음 한 번은 위치(메뉴 계층) 와 사용 대상 을 물어봅니다.
  • 다시 실행하면 고칠 수 있고, 기능 ID는 바뀌지 않습니다.

표의 항목

항목내용
ID프로젝트 코드 기반 (예: GFC-FUC-001)
위치메뉴 계층 1~6 Depth
화면 · 대상어느 화면인지 · 누가 쓰는지
기능명짧게
상세동작 · 조건 · 예외 메시지 · 정책을 번호 매긴 문장으로
우선순위필수 / 선택 등

보는 법

화면 상단 바의 기능명세서 버튼을 누릅니다.

  • 이 화면 탭 — 지금 보고 있는 화면의 기능만
  • 전체 탭 — 프로젝트 전체 (화면이 아직 정해지지 않은 "미정" 기능까지)
  • 표의 셀을 클릭하면 그 기능이 속한 행 범위가 강조됩니다.
여기 적은 명세는 STEP 5에서 Description으로 자동으로 옮겨집니다. 그래서 UI보다 먼저 쓰는 게 이득입니다.

엑셀 양식: templates/기능명세서_양식.xlsx

7STEP 4 — 기능 플로우

등록한 화면들을 기능 단위 여정으로 묶습니다 (예: 회원가입, 결제, 도착 인증).

/pdk-flow FLW-PAY-001 결제

# 형식: /pdk-flow [플로우ID] [플로우이름]

Claude가 묻는 세 가지

  1. 이 기능은 무엇인가요? — 한 줄
  2. 사용자가 어떤 과정을 거치나요? — 예: 상품 선택 → 결제 → 완료
  3. 어떤 화면들이 순서대로 들어가나요? — 등록된 화면 목록에서 고릅니다

결과

  • 좌측 페이지 목록 위에 플로우 Dock이 생깁니다. 플로우를 클릭하면 그 기능의 화면만 다이어그램에 보입니다.
  • 여정 순서상 아직 안 이어진 이동이 있으면 한 번에 확인받고 연결선을 그어 줍니다.
한 화면이 여러 플로우에 들어가도 됩니다 (메인 화면처럼).
여기서 새 화면이 언급되면 그 자리에서 만들어집니다 — 맥락·이동은 /pdk-screen <화면ID> 로 마저 채우세요.

8STEP 5 — 화면 설계

등록한 화면을 하나씩 실제 UI로 그립니다. 플로우 순서대로 진행하면 흐름이 자연스럽게 맞습니다.

/pdk-wireframe SCR-MAIN-001

어떻게 진행되나

  • Claude와 대화하며 화면에 무엇이 있는지 정합니다 — 버튼 · 목록 · 입력칸 등.
  • 실제 문구가 들어간 흑백 와이어프레임으로 그려집니다. 버튼에는 버튼 이름, 목록에는 예시 항목이 들어갑니다.
  • 색·이미지 같은 디자인은 다루지 않습니다. 그건 STEP 6에서 입힙니다.

Description은 자동으로 써집니다

  • STEP 3에서 기능명세를 써 뒀다면 그 내용을 끌어와 만들고, 항목 옆에 기능 ID 칩이 붙습니다 (누르면 기능명세서 표의 그 행으로 이동).
  • 화면에 반영되지 않은 기능이 있으면 마지막에 따로 알려줍니다.
  • 훑어보기용 라벨이라 한 항목당 한 줄 정도로 짧게 적힙니다 (예: 결제하기 → 결제 진행).
  • Description 항목에 마우스를 올리면 화면의 해당 요소가 강조됩니다.
조건에 따라 화면이 달라지면 그렇다고 말해 주세요 (목록 있음/없음, 성공/실패 등). 목업 위에 라디오 버튼이 생겨 상태를 전환해 볼 수 있습니다.

9STEP 6 — 디자인 입히기

Figma 시안을 와이어프레임에 입힙니다. 디자인이 나온 화면만 하면 됩니다.

/pdk-figma-sync SCR-MAIN-001 https://www.figma.com/design/...?node-id=12-34
  • Figma에서 디자인을 가져와 와이어프레임에 적용합니다.
  • 페이지 목록의 디자인 뱃지가 "반영" 으로 바뀝니다.
  • Description의 Figma 링크가 채워집니다.
Figma 데스크탑 앱과 계정 연결이 필요합니다. URL은 노드를 지정한 주소(node-id 가 포함된 것)여야 합니다 — Figma에서 프레임을 선택하고 링크를 복사하면 됩니다.

10결과물 보는 법

index.html 또는 pages/ 안의 화면 파일을 브라우저로 엽니다.

실제 앱처럼 움직입니다

  • 화면 안의 버튼을 누르면 다음 화면으로 이동합니다.
  • 성공/실패처럼 갈라지는 버튼은 누르면 어디로 갈지 고르는 작은 창이 뜹니다.
  • 왼쪽 페이지 목록의 행, 오른쪽 화면 플로우의 노드를 클릭해도 이동합니다.

오른쪽 패널 — 떼어내고 붙이기

  • 헤더를 잡고 밖으로 끌면 떼어내 원하는 곳에 둘 수 있습니다 (네 변·모서리로 크기 조절).
  • 떠 있는 패널을 섹션 위로 끌어오면(위/아래 절반) 또는 헤더의 다시 붙이기 버튼으로 돌아옵니다.
  • 두 패널 사이 선을 끌면 높이 비율이 바뀝니다.
  • 배치는 브라우저 탭을 닫기 전까지 유지됩니다.

11클라이언트 시연 — 포커스 모드

프로토타입을 보여줄 때 씁니다. 목업과 조건 분기 라디오만 남기고 나머지 도구를 모두 숨깁니다.

동작방법
켜기 / 끄기상단 바의 포커스 모드 버튼, 또는 ⌘ + \ (Windows Ctrl + \)
끄기ESC 로도 됩니다
도구 꺼내 보기화면 가장자리에 마우스를 잠시 두면 떠오르고, 떼면 다시 숨습니다
  • 가장자리 위치 — 왼쪽 페이지 목록 · 오른쪽 Description·화면 플로우 · 위 상단 바
  • 시연은 화면 안 버튼을 눌러 진행합니다. 다른 화면으로 넘어가도 포커스 모드는 유지됩니다.
  • 카운트다운처럼 자동으로 넘어가는 화면은 포커스 모드에서만 3초 후 이동합니다 (하단에 남은 시간 표시).
버튼을 눌러도 안 넘어가나요? 이동 연결 전에 만든 화면입니다 — /pdk-wireframe <화면ID> 를 다시 실행하세요.

12PDK 업데이트

PDK가 개선되면 커맨드 한 번으로 최신화합니다. 내 화면은 그대로 남습니다.

/pdk-update

실행하면 순서대로 자동 처리됩니다 — 공통 부분(엔진·커맨드·템플릿·문서) 동기화 → 구조 변경 자동 반영 → 내 수정 재적용 → 변경점 요약 표시.

  • 내 화면·설정은 건드리지 않습니다 — config/, index.html, pages/, assets/mockups/, README.md
  • 덮어쓰기 전 .pdk-backup/ 에 백업합니다.
  • 직접 git pull 할 필요 없습니다 — 커맨드가 다 합니다.

공통 파일을 직접 고쳤다면 — 순서가 중요합니다

/pdk-custom   # ① 내 수정을 patch로 빼둔다
/pdk-update   # ② 최신화 → 그 수정을 자동 재적용
engine/ 같은 공통 파일은 업데이트 때 덮어써집니다. 고친 게 있으면 반드시 /pdk-custom 을 먼저 실행해 빼두세요. (/pdk-update 도 감지해 자동 추출하지만 먼저 빼두는 편이 안전합니다.)

13체크리스트

  • /pdk-init 로 프로젝트 생성 (이름·코드·설명·디바이스)
  • (선택) /pdk-mockup 으로 커스텀 기기 등록
  • 모든 화면을 /pdk-screen 으로 유저플로우 순서대로 등록
  • 화면별 /pdk-description 으로 기능명세서 작성
  • 기능별 /pdk-flow 로 여정 정의 (새로 생긴 화면은 /pdk-screen <화면ID> 로 보강)
  • 화면별 /pdk-wireframe 으로 와이어프레임 + Description 작성
  • 화면별 /pdk-figma-sync 로 디자인 적용
  • index.html 에서 목록·플로우·Description·디자인 최종 확인

14자주 막히는 점

증상해결
화면 플로우에 선이 안 그려짐 화면이 1개면 점만 생깁니다. 이동(다음 화면) 정보를 넣어야 선이 그려집니다.
플로우에 점선 회색 노드가 있음 등록되지 않은 화면 표시입니다. 커맨드로 작업하면 보통 나오지 않습니다 — config/screens.js 를 직접 손댔다면 그 화면 ID를 /pdk-screen 으로 등록하세요.
버튼을 눌러도 화면이 안 넘어감 이동 연결 전에 만든 화면입니다. /pdk-wireframe <화면ID> 를 다시 실행하세요. 이동 자체가 없으면 /pdk-screen <화면ID> 로 먼저 추가합니다.
Description에 마우스를 올려도 강조가 안 됨 그 요소가 /pdk-wireframe 으로 만들어졌는지 확인하세요.
Figma 디자인이 안 보임 Figma 데스크탑 앱·계정 연결이 필요합니다. URL에 node-id 가 있는지 확인하세요.
업데이트 후 내가 고친 게 사라짐 .pdk-backup/ 에 백업이 남아 있습니다. 다음부터는 /pdk-custom → /pdk-update 순서로 실행하세요.
