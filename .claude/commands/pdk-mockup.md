# /pdk-mockup — 커스텀 디바이스 목업 등록

`$1`=디바이스명(레지스트리 key), `$2`=소스(이미지가 담긴 폴더 경로 **또는** Figma URL).
소스를 **참고**해 디바이스 목업(외곽 프레임 + 캔버스 규격)을 만들고 `config/devices.js`에 추가한다.
등록 후 `/pdk-init`의 디바이스 선택지에 나타난다.

> 내장 4종(desktop/mobile/tossfront2/responsive)과 동일한 스키마로 등록되어 화면들이 동일하게 동작한다.
> 사용 도구: Read, Write, Edit, Glob, Bash, (Figma URL인 경우) Figma MCP.

## 절차

### 1) 디바이스명 확인
- `$1`을 레지스트리 key로 쓴다(영문/숫자/하이픈 권장, 예: `kiosk-a`). `config/devices.js`에 **중복 key**면 다른 이름 요청.

### 2) 소스 판별 & 프레임 참고
- `$2`가 **Figma URL**이면: fileKey/nodeId 추출 → `get_screenshot`/`get_design_context`로 프레임 모양(베젤 색·두께·모서리 반경)을 파악한다.
- `$2`가 **폴더 경로**이면: `Glob`으로 이미지(`*.png|jpg|jpeg|svg|webp`)를 찾는다.
  - **여러 장이면** `AskUserQuestion`으로 한 장을 고르게 한다(목업 프레임 기준 이미지).
  - 1장이면 그것을 사용. 0장이면 경로를 다시 묻는다.
- 참고 이미지를 `assets/mockups/$1/`에 저장한다(`Bash`로 복사/다운로드, 보관·미리보기용).

### 3) 캔버스 규격 입력 (대화)
- **화면(콘텐츠) 가로×세로(px)** 를 사용자에게 직접 묻는다(예: 720 × 1280).
- 베젤도 확인한다: **두께**(기본 10px), **색**(기본 `#404040`), **모서리 반경**(기본 24px). 소스에서 파악된 값이 있으면 그 값을 제안.

### 4) `config/devices.js` 갱신
- 다음 항목을 추가한다(type: `frame` = 미니멀 베젤 프레임, 엔진이 CSS로 렌더):
```js
'<$1>': {
  label: '<표시 이름>',
  type: 'frame',
  width: <가로>, height: <세로>,
  bezel: <두께>, radius: <반경>, bezelColor: '<색>',
},
```
- 기존 항목은 보존하고 **추가만** 한다.

### 5) 안내 & (선택) 미리보기
- 등록 완료를 알리고, `/pdk-init`에서 `$1`을 선택할 수 있음을 안내.
- 원하면 `pages/preview-<$1>.html`을 다른 화면 파일과 동일 패턴으로 생성해 바로 확인하게 한다
  (`index.html`을 제외한 모든 페이지 HTML은 `pages/`에 두고, 공통 경로는 `../`로 참조)
  (config 로드 후 인라인으로 `window.PDK_PROJECT.device='<$1>'` 설정).

## 참고 / 한계
- 현재 엔진의 `type:'frame'`은 **CSS 베젤(단색·그라데이션 + 둥근 모서리)** 로 렌더한다.
  사진 같은 **실물 프레임 이미지를 그대로 오버레이**하려면 엔진의 이미지-프레임 지원(향후 확장)이 필요하다.
  지금은 소스를 **참고**해 가장 가까운 CSS 프레임으로 등록한다.
- `tossfront2`처럼 상세 키오스크 목업이 필요하면 `type:'kiosk'` + 전용 CSS가 필요(향후).
