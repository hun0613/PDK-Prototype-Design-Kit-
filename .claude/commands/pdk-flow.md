# /pdk-flow — 기능 플로우 등록

`$1`=플로우ID, `$2`=플로우이름. 기능(feature) 단위의 **사용자 여정(User Journey)** 을 정의한다.
플로우는 화면(screen)의 **상위 그룹** 으로, 여러 화면을 하나의 기능 시나리오로 묶는다.

> `/pdk-screen`이 개별 화면과 화면 간 이동을 정의한다면,
> `/pdk-flow`는 "이 기능을 사용할 때 어떤 화면들을 거치는가"를 정의한다.

## UI 동작 (엔진 연동)

등록된 플로우는 엔진이 `config/flows.js`를 읽어 다음과 같이 표현한다:

1. **좌측 페이지 목록 패널 상단에 플로우 Dock** — 플로우 이름·ID 목록이 칩/탭 형태로 표시.
2. **플로우 클릭 → 해당 플로우의 소속 화면만** 플로우 다이어그램에 표시(나머지 노드는 숨김).
3. **"전체" 또는 일반 페이지 클릭 → 전체 다이어그램** 표시(현재 동작 유지).

> 엔진의 플로우 Dock UI 및 다이어그램 필터링은 이 커맨드가 아닌 엔진 업데이트(`engine/common.js`)에서 구현한다.
> 이 커맨드는 **데이터(config/flows.js) 생성·관리** 만 담당한다.

## 절차

### 1) 인자 확인
- 플로우ID/플로우이름을 확정한다. 누락 시 사용자에게 물어본다.
- 플로우ID 규칙 권장: `FLW-<기능약어>-<3자리>` (예: `FLW-AUTH-001`). 강제는 아님.
- `config/flows.js`를 읽어 **중복 ID**가 있으면 경고하고 다른 ID를 요청한다.

### 2) 기능 설명 수집 (대화형)
다음을 물어본다(짧고 쉽게):
1. **이 기능은 무엇인가?** — 한 줄 설명. → `description`에 저장.
2. **사용자 시나리오**: 이 기능을 사용할 때 사용자가 거치는 과정을 간단히 설명.
   - 예: "QR 인증 → 예약 확인 → 도착 완료"

### 3) 소속 화면 지정
- `config/screens.js`를 읽어 **등록된 화면 목록**을 사용자에게 보여준다(ID·이름·카테고리).
- 사용자가 이 플로우에 포함될 화면들을 **순서대로** 선택하게 한다.
  - 화면ID를 직접 나열하거나, 번호로 선택하거나, "전체 카테고리" 단위로 묶을 수 있다.
  - 순서는 사용자 여정 순서(시작 화면 → 종료 화면)를 따른다.
- 아직 `/pdk-screen`으로 등록하지 않은 화면ID도 허용한다(ghost). 나중에 등록되면 자동 연결.
- 결과를 `screens: ['SCR-001', 'SCR-002', ...]` 배열에 저장한다.

### 4) `config/flows.js` 갱신

파일이 없으면 생성, 있으면 Read 후 Edit한다.

```js
/* PDK 기능 플로우 — 화면의 상위 그룹. 플로우 Dock · 다이어그램 필터링에 사용.
 *
 * flow 스키마:
 *   id          — 플로우 고유 ID (예: FLW-AUTH-001)
 *   label       — 플로우 표시 이름 (예: 도착 인증)
 *   description — 기능 한 줄 설명
 *   screens     — 소속 화면 ID 배열 (사용자 여정 순서)
 *
 * 예시:
 *   { id: 'FLW-AUTH-001', label: '도착 인증',
 *     description: 'QR 인증으로 예약을 확인하고 도착 완료 처리',
 *     screens: ['SCR-ATH-001', 'SCR-ATH-002', 'SCR-ATH-003'] }
 */
window.PDK_FLOWS = [];
```

플로우 객체를 배열에 추가한다:
```js
{
  id: '<플로우ID>',
  label: '<플로우이름>',
  description: '<기능 한 줄 설명>',
  screens: ['<화면ID-1>', '<화면ID-2>', ...],   // 사용자 여정 순서
}
```

### 5) `index.html` 로더 확인
- `index.html`의 스크립트 로더에 `config/flows.js`가 포함되어 있는지 확인한다.
- 없으면 로더의 `files` 배열에 `'config/flows.js'`를 추가한다.
  ```js
  var files = ['config/devices.js', 'config/project.js', 'config/screens.js', 'config/flows.js', 'engine/common.js'];
  ```
- 각 화면 HTML에도 동일한 로더가 있으면 같이 갱신한다.

### 6) 안내
- 추가된 플로우ID/이름/소속 화면 수를 요약한다.
- 엔진이 플로우 Dock + 다이어그램 필터링을 지원하면, 브라우저에서 확인 가능함을 안내.
- 다음 단계 안내:
  - 플로우 추가: `/pdk-flow [플로우ID] [플로우이름]`
  - 소속 화면이 아직 없으면: `/pdk-screen`으로 화면 먼저 등록
  - 플로우에 화면 추가/제거: `/pdk-flow [기존 플로우ID]`로 재실행해 수정

## 기존 플로우 수정 모드

`$1`이 이미 등록된 플로우ID이면 **수정 모드**로 진입한다:
- 현재 상태(이름·설명·소속 화면)를 보여주고, 무엇을 바꿀지 물어본다.
- 화면 추가/제거/순서 변경을 지원한다.
- 이름·설명도 변경 가능.

## 주의
- 한 화면이 **여러 플로우에 동시에 소속**될 수 있다(예: 메인 화면은 모든 플로우의 시작점).
- `flow.to`(화면 간 이동 관계)는 건드리지 않는다 — 이미 `/pdk-screen`에서 정의됨.
- 플로우 데이터는 다이어그램 **필터링(표시 범위)** 에만 사용되며, 화면 간 간선을 새로 만들지 않는다.
- 기존 `config/screens.js`는 수정하지 않는다(플로우 매핑은 `flows.js`에서 단방향 참조).
- 엔진 UI(Dock·필터링)는 이 커맨드의 범위가 아니다 — 엔진 업데이트로 별도 구현.
